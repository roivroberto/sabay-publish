# Sabay Publish web application

The Next.js, Convex, and Clerk application behind Sabay Publish's bilingual editorial workflow.

For the product overview and presentation material, start with the [repository README](../README.md).

## Local setup

```bash
pnpm install
cp .env.example .env.local
```

The minimum local configuration is documented in [`.env.example`](.env.example). It covers:

- Clerk browser and server credentials;
- Clerk's Convex JWT issuer and webhook signing secret;
- the local site URL;
- Convex development values generated by `pnpm convex:dev`;
- optional Google Cloud Translation credentials.

Variables consumed by files under `convex/` must also exist in the selected Convex deployment. After updating local backend credentials, synchronize them with:

```bash
pnpm convex:sync-env
```

Start the backend and application in separate terminals:

```bash
pnpm convex:dev
pnpm dev
```

## Verification

```bash
pnpm lint
pnpm typecheck
pnpm build
pnpm test:e2e
```

Playwright starts the local services, uses a controlled translation path, and exercises the writer, editor, review, and publication workflow. Authenticated runs require the Clerk test values documented in `.env.example`.

## Deployment

The application can be hosted on Vercel with `web/` as the project root while Convex remains the backend deployment. Configure the same canonical site URL and compatible Clerk, Convex, and Google Cloud values in their respective hosted environments.

Keep service-account JSON and signing secrets in the deployment providers. Do not commit them to the repository.

## Translation behavior

Google Cloud Translation produces a draft. The editor can revise or reject that draft before publication, and the public article is not released until the workflow reaches its approved state.
